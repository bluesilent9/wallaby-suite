Connected nodes & wallet ownership+

Query every connected Bitcoin Core node through Wallaby Agent, merge matching public-descriptor replicas and assign family ownership and SMSF status. Historical wallets come from labelled fixed-address watch-only groups in Core; the Extinct Wallets ODS upload has been removed.

Node-based history & verified balances+

Reconstruct wallet history, balances and acquisition costs from connected nodes. There is no public-blockchain fallback: pruned nodes must retain the required wallet transactions, and missing evidence stops an incomplete trace. Wallet Key Explorer has been removed.

Australian CGT working papers+

Combine Bitaroo PDFs, Exchanges ODS, ownership and pricing records. Review per-user financial-year totals, gains, losses, holding periods, parcel allocation and offline HTML reports. Build 7 handles declared no-compensation C1 losses from traced reduced cost base; declarations and working papers require review.

Visual transaction builder+

Create payment diagrams and reusable templates, allocate fees, send maximum amounts and prepare unsigned PSBTs. Compose unsigned vault proposals with other payments, then request verified partial signatures through locally authorised Agents. Single and multiple senders use the same PSBT workflow; broadcast is separately approved.

Fees, blocks & transaction tracking+

Use Core-driven fee estimates, pending/mined block views adapted from Mempool, transaction tracking and Core fee-unit conversions. Blockchain and fee evidence use your nodes; market/currency pricing remains external.

Family tools & saved records+

Use the shared Address Book, ownership-aware wallet cards, notifications, saved transaction workflows and validated profile archives. Each user sees their own tax totals and history; shared records stay on your server behind authorised SSH tunnels.

Vaults & verified wallet synchronisation+

Dashboard Build 12 and Agent Build 11 implement signed initial previews, complete wallet request lists with frozen paired identities and explicit retries after local reconciliation. Users compare identity and snapshot codes directly. Private files travel between Agents, never Dashboard. Vault monitoring and Agent-authorised PSBT signing/broadcast are implemented.

WALLABY AGENTV2 · Development Build 11

YOUR LOCAL APPROVAL AND SIGNING WORKSPACE

Connect. Review.
Sign with confidence.

Manage IPv6 services and locally approve Bitcoin wallet operations. Agent V2 Development Build 11 adds a persistent local wallet-sync Denial list, alongside guided optical-archive restoration, multisignature message proofs and a live authorisation queue.

  • DDNS-GO, Dashboard access and node reporting share authenticated IPv6 SSH.
  • Disc Operations loads encrypted archival signing accounts into protected RAM. New backups repeat checksummed encrypted copies across the available disc.
  • Sign Message uses local node or disc-loaded accounts, with BIP-322 single-key and multisignature proofs.
  • Authorise independently reviews transaction requests, wallet policies and synchronisation choices. Sidebar dots show unresolved work.
  • Pruned-node history recovery keeps the node’s existing pruning settings.

Dashboard Build 12 already routes locally restored cosigner signatures. The wallet-sync Denial list now persists locally on the Agent across restarts. Dashboard Build 12 queries the Agent’s current signed permission status and suppresses redundant offers or warnings. There is no second exclusion setting to clear.

Protected desktop startup and real optical hardware need deployment validation. Read the repository’s signing audit warning before handling real keys.
